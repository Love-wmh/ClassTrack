# 课程表行高不齐与竖向滚动条

> 发生时间：2026-09-11  
> 复现环境：桌面 Web（`localhost:5173`）、Android Capacitor App 真机  
> 关联页面：课程表  
> 状态：已修复，真机确认 12 节等高，且课表区域不再出现竖向滚动条

## 现象

课表总高度已经能占满导航栏上方的剩余空间，但内部行高不稳定：

- 有课的行明显高于空行
- 跨两节的课程会把相邻行一起撑高
- 第 9 到 12 节明显变矮
- 用 JS 按容器高度均分行高后，课表区域又出现竖向滚动条

期望结果是：课表总高度保持当前方案，12 节高度完全相等，跨节课程只覆盖对应行，不出现竖向滚动条。左右滑动时，左侧“节”列仍然固定。

## 根因

问题不在某一行的 Tailwind 类写错，而在 HTML 表格自身的高度算法。

### 1. 表格行的 `height` 只是最小高度

原先用 `<table>` 渲染课表，行高写成：

```tsx
<tr className="h-[calc((100%-2.25rem)/12)] min-h-[40px]">
```

对表格来说，这只是建议高度。只要单元格内容更高，浏览器就会把这一行继续撑高。课程格里还有：

```tsx
min-h-[74px]
```

有课的格子因此比空行更高。

### 2. `rowSpan` 会打乱均分结果

跨节课程使用 `rowSpan` 合并单元格。表格在计算跨行单元格高度时，会把内容高度摊到被合并的多行上，而不是先把 12 行均分再让课程去覆盖。于是：

- 有跨节课的区域变高
- 后面没有课的行被压缩
- CSS 百分比行高失效

### 3. 用 JS 写像素高度也无法锁死表格行

后续改成 `ResizeObserver` 测量容器高度，减去表头后再除以 12，把像素高度写到 `<tr>` 上。这仍然失败，因为：

- 表格行高依旧是最小高度，不是最大高度
- 小数像素、边框和课程内容会把总高度再撑出容器
- 容器开着 `overflow-auto`，多出来的几像素就会变成竖向滚动条
- 给行加 `max-height` 后，跨行单元格和内容最小高度仍可能突破限制

所以只要课表还是 `<table> + rowSpan`，就很难同时做到“总高度占满”和“每行等高”。

## 无效方案

下面这些改法都验证过，不能稳定解决：

- 去掉 `min-h-[74px]`，只保留 CSS `calc((100% - 2.25rem) / 12)`
- 给 `td` 写 `h-px` / `h-0`，让子元素按百分比继承高度
- 用 `ResizeObserver` 计算行高，再写到 `<tr style={{ height }}>`
- 读取表头实际高度后再均分，避免硬编码 36px
- 给行和单元格同时写 `height` 和 `max-height`，并关闭竖向滚动

它们都没有改变这件事：表格行高由内容决定，`rowSpan` 会继续干扰分配。

## 有效方案

放弃 HTML 表格，改用 CSS Grid 画课表。

### 1. 用 Grid 均分剩余高度

课表容器仍然占满页面剩余高度。内部网格定义为：

```tsx
grid-cols-[3.5rem_repeat(7,minmax(0,1fr))]
grid-rows-[2.25rem_repeat(12,minmax(0,1fr))]
```

- 第一列是节次，第一行是星期
- 下面 12 行使用 `1fr`，由浏览器直接均分剩余空间
- 不再计算像素行高，也不再依赖表格的最小高度算法

### 2. 跨节课程用 `grid-row` 覆盖，而不是合并单元格

课程放到对应列，并用：

```tsx
gridRow: `${course.startSection + 1} / ${course.endSection + 2}`
```

覆盖起始节到结束节。空格子单独占一格。这样跨节课程只是叠在已经均分好的行上，不会把别的行撑高。

### 3. 课程格不再设置最小高度

`ScheduleCourseCell` 去掉 `min-h-[74px]` 和备注区的 `min-h-[18px]`，改为 `min-h-0`，内容超出格子时省略，不再反向撑高网格行。

### 4. 只保留横向滚动

容器使用：

```tsx
overflow-x-auto overflow-y-hidden
```

节次列继续 `sticky left-0`。课表总高度由外层 flex 分配，内部不再出现竖向滚动条。

## 后续注意

课表这类“固定行数、需要占满剩余高度、还有跨行块”的布局，不要再用 `<table>` 做视觉网格。表格适合数据表，不适合时间轴。以后如果要改节次数、星期列或安全区，优先调整 Grid 的 `grid-template-rows` / `grid-template-columns`，不要回到 `rowSpan` 和 JS 量行高。
