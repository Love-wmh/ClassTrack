# 手机导出没有文件

> 发生时间：2026-09-15  
> 复现环境：Android Capacitor App（`com.classtrack.app`）真机  
> 关联页面：代课管理、数据管理、课程备注弹窗  
> 状态：已修复，并在真机确认系统分享面板可以打开

## 现象

手机点击「导出当前记录」后：

- Toast 显示「已开始下载」
- 系统没有下载通知
- 文件管理器、微信、下载目录都找不到文件

期望结果是：导出后能真正拿到文件，而不是只提示成功。

## 根因

业务层把浏览器下载当成了全平台方案。

代课管理、数据备份、备注弹窗原先分别使用：

- `file-saver` 的 `saveAs()`
- `jspdf` 的 `pdf.save()`
- 创建一个隐藏 `<a download>` 再点击

这些在桌面浏览器里会触发下载。Capacitor Android WebView 没有浏览器下载栏，点击后 JS 仍返回成功，所以 Toast 会先弹出，文件却不会落盘。

方案文档里已经记过这个风险：`docs/pwa-capacitor-android.md` 明确写过 PDF/Word 在 Android WebView 中不稳定，后续应接入 Filesystem / Share。

## 无效方案

继续在 WebView 里模拟浏览器下载，不能稳定解决：

- 换 `saveAs` 为 `<a download>`
- 只改 Toast 文案
- 只给代课管理接原生能力，其他导出入口仍走浏览器下载

它们都没有改变这件事：原生容器不会接管 WebView 的假下载。

## 有效方案

新增统一导出适配层 `app/lib/exportFile.ts`：业务只提交文件名、MIME 和数据，由适配层按平台分流。

- 浏览器 / PWA：继续本地下载
- 原生 App：写入应用缓存，再打开系统分享面板

三个导出入口都改为调用 `exportFile()`：

- 代课管理：PDF / Word / Markdown / HTML / TXT
- 数据管理：JSON 备份
- 课程备注弹窗：Markdown

原生侧接入 `@capacitor/filesystem` 和 `@capacitor/share`。用户取消分享不当失败；真正打开分享面板后再提示「请选择保存位置或分享应用」。
