# 学期选择与历史数据迁移设计方案

## 背景

当前 ClassTrack 的课程、考勤标记、当前周次和第一周第一天都以一份全局数据保存在浏览器 `localStorage` 中，持久化键为 `class-track-storage`。现有数据模型默认应用只有一个学期：

- `classes`
- `classMarks`
- `currentWeek`
- `firstWeekStartDate`
- `school`
- `isInitialized`

本次需求是在“个人中心 / 学期设置”中加入学期选择能力：右侧使用选择输入框选择已经创建的学期，输入框右侧提供“新建学期”按钮。同时需要自动迁移旧版本本地数据，让已经使用过项目的用户升级后无需手动导入或丢失历史数据。

## 目标

1. 支持多个学期并存，每个学期拥有独立的课程、考勤标记、当前周次和第一周第一天。
2. 学期设置区域新增“当前学期”行，右侧为学期选择框和“新建学期”按钮。
3. 切换学期后，课表、数据看板、课程管理、数据管理等页面展示当前学期的数据。
4. 旧版 `localStorage` 中的单学期数据在应用启动时自动迁移为一个默认学期。
5. 迁移逻辑幂等：重复执行不会重复创建学期，也不会覆盖用户已经迁移后的多学期数据。
6. 数据导入导出同时兼容旧版备份和新版多学期备份。

## 非目标

1. 本阶段不做云同步或后端存储。
2. 本阶段不做学期删除、重命名和归档，除非后续需求明确要求。
3. 本阶段不改造课程解析器的核心解析逻辑，只把导入结果写入当前学期或新建学期。

## 新数据模型

### 新增类型

文件：[app/lib/types.ts](/Users/wangminghuang/WebstormProjects/ClassTrack/app/lib/types.ts)

建议新增：

```ts
export interface Semester {
  id: string
  name: string
  code: string
  schoolId?: string
  classes: Class[]
  classMarks: Record<string, ClassMark>
  currentWeek: number
  firstWeekStartDate: string | null
  createdAt: string
  updatedAt: string
}
```

字段说明：

- `id`：应用内唯一标识，建议格式 `semester-${timestamp}-${random}`。
- `name`：展示名称，例如 `2025-2026 第二学期` 或 `2025-2026-2`。
- `code`：教务系统学年学期代码，优先来自课程数据中的 `Class.semester` 或书签脚本输入的 `term`。
- `schoolId`：学期所属学校，可用于不同学校数据并存。
- `classes/classMarks/currentWeek/firstWeekStartDate`：该学期独立业务数据。
- `createdAt/updatedAt`：用于排序、迁移审计和导出。

### AppData 调整

建议 AppData 扩展为：

```ts
export interface AppData {
  school: School | null
  classes: Class[]
  classMarks: Record<string, ClassMark>
  currentWeek: number
  isInitialized: boolean
  firstWeekStartDate: string | null
  semesters: Semester[]
  currentSemesterId: string | null
  schemaVersion: 2
}
```

保留顶层 `classes/classMarks/currentWeek/firstWeekStartDate` 的目的：

1. 兼容现有页面和 hooks。
2. 降低迁移风险。
3. 让当前学期数据读取仍然是 O(1)，不用所有页面都通过 selector 查找。

长期可以再清理为只读 `activeSemester` selector，但不建议和本次需求混在一起做。

建议第一版用弹窗完成，不把复杂表单塞进设置行里：

字段：

- 学期名称，必填，例如 `2025-2026 第二学期`。
- 学期代码，选填，例如 `2025-2026-2`，用于书签脚本和导入识别。

2. 自动设为当前学期。

1. 顶层字段作为当前学期快照。
2. 当前学期对象作为真实多学期集合中的持久副本。
3. 修改课程、标记、周次、第一周第一天时，同时写入顶层字段和当前学期。

需要改造的现有 actions：

- `setClasses`
- `setClassMarks`
- `toggleAttendance`
- `markWeekAsAttended`
- `markWeekAsUnattended`
- `setNote`
- `setCurrentWeek`
- `resetData`
- `importClasses`

示例原则：

```ts
setFirstWeekStartDate: (date) => {
  set((state) => {
    state.firstWeekStartDate = date
    const semester = state.semesters.find((item) => item.id === state.currentSemesterId)
    if (semester) {
      semester.firstWeekStartDate = date
      semester.updatedAt = new Date().toISOString()
    }
  })
}
```

切换学期时：

```ts
setCurrentSemester: (semesterId) => {
  set((state) => {
    const semester = state.semesters.find((item) => item.id === semesterId)
    if (!semester) return

    state.currentSemesterId = semester.id
    state.classes = semester.classes
    state.classMarks = semester.classMarks
    state.currentWeek = semester.currentWeek
    state.firstWeekStartDate = semester.firstWeekStartDate
    state.isInitialized = semester.classes.length > 0 || state.isInitialized
  })
}
```

## 自动迁移设计

### 迁移入口

推荐使用 Zustand persist 的 `version` + `migrate`：

```ts
persist(
  immer(...),
  {
    name: 'class-track-storage',
    version: 2,
    migrate: migrateClassTrackStorage,
    partialize: ...
  }
)
```

这样能直接处理 Zustand 反序列化后的 `state` 对象，不需要手动提前读写 `localStorage`。

### 迁移判断

判定为旧版数据的条件：

- 没有 `schemaVersion`，或 `schemaVersion < 2`
- 没有 `semesters`，或 `semesters` 不是数组
- 存在旧顶层字段之一：`classes/classMarks/currentWeek/firstWeekStartDate`

判定为已迁移数据的条件：

- `schemaVersion === 2`
- `semesters` 是数组
- `currentSemesterId` 指向已有学期，或 `semesters` 为空

### 旧数据生成默认学期

从旧数据创建一个学期：

```ts
const migratedSemester: Semester = {
  id: inferSemesterId(oldState),
  name: inferSemesterName(oldState),
  code: inferSemesterCode(oldState),
  schoolId: oldState.school?.id,
  classes: oldState.classes ?? [],
  classMarks: oldState.classMarks ?? {},
  currentWeek: oldState.currentWeek ?? 1,
  firstWeekStartDate: oldState.firstWeekStartDate ?? null,
  createdAt: now,
  updatedAt: now,
}
```

推断策略：

1. `code` 优先取第一条课程的 `semester`。
2. 如果课程中存在多个 `semester`，取数量最多的那个作为默认学期代码，并在迁移文档注释中记录这种情况。现有旧结构本身无法可靠拆分多学期，因为 `classMarks` 的 key 是 `classId-week`，如果跨学期课程 id 冲突会有歧义，所以自动迁移只创建一个默认学期最稳妥。
3. `name` 优先格式化 `code`，无法格式化时使用 `历史学期`。
4. `id` 建议稳定生成，例如 `migrated-${hash(code + firstWeekStartDate + classes.length)}`，避免重复迁移产生多个相同学期。

### 空旧数据处理

如果旧数据没有课程：

- 创建空学期不是必须的。
- 更推荐迁移为：

```ts
semesters: []
currentSemesterId: null
classes: []
classMarks: {}
currentWeek: 1
firstWeekStartDate: null
schemaVersion: 2
```

这样首次使用用户会看到空状态，并可以通过“新建学期”或导入流程创建学期。

### 幂等规则

迁移函数必须满足：

1. 如果已经存在 `semesters`，不再根据顶层旧字段创建新学期。
2. 如果 `currentSemesterId` 无效但 `semesters` 非空，默认选择第一个学期，并同步顶层字段。
3. 如果 `classes/classMarks/currentWeek/firstWeekStartDate` 与当前学期不一致，以当前学期为准，避免旧快照覆盖多学期数据。
4. 迁移过程中不删除旧字段，因为本设计仍需要顶层当前学期快照。

## 导入流程改造

文件：[app/components/import-flow/useImportFlow.ts](/Users/wangminghuang/WebstormProjects/ClassTrack/app/components/import-flow/useImportFlow.ts)

### 解析器导入

导入课程 JSON 后：

1. 解析得到 `classes`。
2. 读取课程中的 `semester` 作为 `code`。
3. 如果当前没有学期，则自动创建一个学期并设为当前学期。
4. 如果当前已有学期，则把课程导入当前学期。
5. 如果导入文件中的学期代码和当前学期 `code` 不一致，建议弹出确认：
   - 覆盖当前学期
   - 新建学期并导入

第一版可以简化为：

- 如果当前学期为空或没有课程，直接导入当前学期。
- 如果当前学期已有课程且代码不同，新建学期导入，避免误覆盖。

### 书签脚本学期代码

当前书签脚本安装步骤里有 `term` 输入。新增学期后建议：

- 默认 `term = currentSemester.code || bookmarkletAdapter.defaultTerm`。
- 当用户在导入流程中修改 `term`，不立即修改当前学期 `code`。
- 成功导入后再根据解析结果或 `term` 更新当前学期 `code/name`。

## 课程标记 key 风险

当前 `classMarks` 的 key 是：

```ts
`${classId}-${week}`
```

多学期后由于每个学期有独立 `classMarks` 对象，所以 key 暂时不需要改。

不建议把 key 改成 `${semesterId}-${classId}-${week}`，因为：

1. 会增加迁移复杂度。
2. 当前标记只在学期内部使用。
3. 独立学期容器已经解决跨学期冲突。

## 回滚策略

如果上线后发现迁移问题：

1. 因为仍然使用同一个 `localStorage` key，优先提醒用户通过“数据管理”导出备份。
2. 新版导出包含完整多学期数据，可作为恢复依据。
3. 迁移函数不应删除旧顶层字段，因此即使 `semesters` 创建失败，仍可从顶层字段恢复当前学期数据。

## 关键决策

1. 使用 `semesters + currentSemesterId` 保存多学期。
2. 保留顶层字段作为当前学期快照，降低本次改造范围。
3. 自动迁移旧数据为一个默认学期，不尝试拆分历史多学期。
4. 学期内继续使用现有 `classMarks` key，不引入 semester 前缀。
5. 新建学期第一版只创建空学期，导入流程负责填充课程数据。
