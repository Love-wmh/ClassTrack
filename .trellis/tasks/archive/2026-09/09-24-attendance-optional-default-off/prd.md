# 出勤能力默认关闭并做成可选项

> 2026-09-24 用户口径：**「把上课和不上课统计默认关闭吧，做成可选项」**。
> 范围确认为**整块出勤能力**（课表标记 + 数据看板出勤统计），不是只隐藏看板某几张卡。
>
> 本任务含四支改动，各自有独立可验证的验收项：
> **A 开关本体**（默认关 + 个人中心可开启）→ **B 课表侧的出勤标记入口随开关隐藏** →
> **C 数据看板侧的出勤统计随开关隐藏**（保留与出勤无关的课程分布统计 + 一条提示卡）→
> **D 备注与出勤解耦**（`ClassMark` 补一个「这一条是否做出勤判断」的字段，schema v3 → v4）。
>
> D 的来源：本任务原本把「写备注会给未标记课次留下缺勤标记」列为**不动**的已知取舍；用户 2026-09-24 听完代价后**改选「本次一起修」**。D 与 A/B/C 无依赖，可独立验证、独立回滚。

## Goal

「这节课上没上」这套东西（课表上的已上/未上标记 + 看板的完成度/缺勤率/周趋势/风险课程）
**默认不出现**在界面上，用户在**个人中心**打开开关后才出现。已记录的出勤数据一律不删除。

另外修掉一笔老账：**写备注不再等于缺勤**。只写了备注、没做出勤判断的课次，从此记成「未标记」而不是「缺勤」，
不再在用户开启开关时凭空造出一片缺勤（见 R9 与「决策记录」）。

## Requirements

### R1 开关默认关闭

- 首次安装 / 存储里从未写过该设置 → **关闭**。
- 存储里的值非法（手改、旧版本、别的应用写的同名键）→ 回落**关闭**，不抛异常。
- 已写入 `enabled: true` 的设备 → 保持开启。

### R2 个人中心可开启

- 个人中心新增「出勤统计」卡片，一个 Switch，切换立即生效、刷新后保持。
- 卡片要如实说明：开启后能做什么、关闭时哪些东西看不到、**已记录的数据不会被删除**。

### R3 课表侧随开关隐藏（关闭时）

- 课程格：不显示状态色条、外圈和右下角角标图标；`title` 不再出现「已上/未上」。
- 顶栏：不渲染「全部已上」「全部未上」两个按钮，也不渲染它们的确认弹窗；手机端顶栏列数随之收窄。
- 课程详情弹窗：不渲染出勤切换按钮。
- **备注不受影响**：课程格仍显示备注、弹窗仍可编辑保存备注。

### R4 数据看板随开关隐藏（关闭时）

- 不渲染：截止今日完成度、截止今日缺勤率、总课程完成度、标记覆盖率、未标记课次、周趋势、风险课程、课程完成度排行。
- 保留但去掉出勤系列：星期分布（只留「总课次」）、节次分布（只留「总课次」）。
- 保留不变：课程实例、总课次数量、备注数量、课程类别分析、课程性质分析。
- 顶部出现一条提示卡：说明出勤统计已关闭、开启后恢复哪些内容，并提供去个人中心的入口。
- 页面副标题与空态文案不得再承诺「完成度、缺勤率」（关闭时）。

### R5 计数行随开关隐藏

- 个人中心与数据管理的「已标记课程」行，关闭时不渲染；「有备注课程 / 课程总数」保持。

### R6 数据保留与 schema 升级

- `classMarks` 一律保留：关闭开关不删除、不过滤、不重写任何标记；导出备份仍包含 `classMarks`；重新开启后数据完整回来。
- 备份契约保持兼容：旧备份（没有 D 的新字段）能照常导入，导入后该字段按「已做出勤判断」补齐。
- schema 版本 `3 → 4`，四处字面量同步；`partialize` 字段列表不变（新字段在 `classMarks` 值里面）。

### R7 开启时行为逐项不变

- 开关打开后，课表与看板的呈现、文案、交互与改动前**逐项一致**（这是回归要求，不是新设计）。

### R8 文档同步

- README 的功能说明与「管理课程」小节必须如实反映「出勤默认关闭、可在个人中心开启」。
- spec 侧：`mobile-schedule-layout.md` 补顶栏条件列数、`state-management.md` 补新 store。

### R9 备注不再被当成缺勤（D 支线）

- 给 `ClassMark` 补一个必填字段，含义是**这一条标记是否包含一次真实的出勤判断**：
  - `toggleAttendance`、`markWeekAsAttended`、`markWeekAsUnattended`、导入时的 `createPastClassMarks` → 写「已判断」；
  - `setNote` 在标记不存在时新建的那一条 → 写「未判断」（只写了备注，没做出勤判断）。
- 统计口径随之修正：**「未判断」的课次算「未标记」，不再算「缺勤」**（缺勤率、风险课程、标记覆盖率、周趋势、星期分布、课程完成度排行、完成度都要一致）。
- 旧数据（没有该字段）一律补成「已判断」：**现有统计一个数都不变**。老账无法反推（存储里「只写了备注」与「标了未上又写备注」完全同形），这一点必须如实写进技术文档。
- 三个判据（已上 / 缺勤 / 未标记）收敛成单一来源的谓词函数，不允许在看板里散落重复的过滤表达式。

## 决策记录：为什么这次要修「写备注 = 缺勤」

原本列为**已知取舍**（本次不动）。用户听完代价后改选**本次一起修**，因此它变成 R9 的正式要求。

**问题**：`setNote` 在标记不存在时会新建 `{isAttended: false, note}`，而看板把 `isAttended === false` 一律算缺勤。
于是「只写了一句备注」隐含了一次用户从没做过的「缺勤」判定 —— 今天开着出勤就能看到（课程格立刻变红、缺勤率 +1）；
出勤默认关闭之后更严重：备注成为标记的唯一来源，用户将来一开开关就是一片虚假缺勤。

**为什么没有中间方案**：存储里「只写了备注」与「标了未上又写了备注」完全同形（都是 `isAttended: false` + note 非空），
用启发式去猜会把真正请假/旷课的课次也误判成未标记。所以只能显式记下「这一条是否做出勤判断」。

**老数据怎么办**：没有该字段的标记一律按「已判断」处理 —— 现有统计零变化。老账无法反推，
这一点在技术文档里如实记录，不对外承诺「历史缺勤率已经被修正」。

## Notes

- 「关闭 = 不显示」，不是「清数据」：任何一处实现都不得删除、过滤或重写 `classMarks`。
- 诚实性口径（沿用本项目既有做法）：关闭时提示卡与设置卡都要说清「数据没删、开启后回来」，
  不能让用户以为标记丢了。
