# 更新检测：回前台自动检查失效与更新说明按纯文本渲染

## Goal

1. **回前台的自动检查要真的能拿到更新**：节流窗口只由「拿到结果的那次检查」消耗，请求失败不消耗；
   间隔档位补上更细的粒度，默认从 1 天收到 1 小时。
2. **「发现新版本」模态框里的更新说明按真实 markdown 渲染**（标题、列表、粗体、行内代码、链接、引用、分隔线），
   且不为此新增任何 HTML 注入面。

## 背景与现状事实

| 事实 | 后果 |
| --- | --- |
| `app/components/app-update/useAppUpdate.ts` 的 `shouldCheckNow` 是自动检查唯一的闸门；同一函数在**发请求之前**就 `markChecked(now)`，并且**失败也记**（`app/lib/app-update/schedule.ts` 的文档明确这么设计） | 冷启动那一次已经把窗口消耗掉 → 之后切前台被闸门直接 `return`。用户看到的正是「回到前台什么都不发生，只有『立即检查』能拿到更新」 |

| 本机实测过的存储现场：`{channel:"all",autoCheck:true,notify:true,interval:"1d",lastCheckAt:1790168831899,…}`（`archive/2026-09/09-23-update-check-notify/evidence/device-06-real-api-store.txt`） | 存量设备里已经有 `interval:"1d"`。**只改默认值不影响这些设备**，必须有一次性的存量提升，否则本次修复对上报问题的设备不生效 |
| release 正文的真实形态（`GET /repos/Love-wmh/ClassTrack/releases?per_page=5` 实测）：`ClassTrack Android **1.0.18-beta**`、`## 本次改动`、`- feat(...) (sha)`、行内 `` `code` `` | 现在是「去掉 `**` + `whitespace-pre-wrap`」的纯文本（`updateDialogCopy.ts` 的 `formatReleaseNotes`），`##` 与 `-` 原样显示 → 用户说的「md 以纯文本样式展示」 |
| 上一轮任务 `archive/2026-09/09-23-update-check-notify/prd.md` 决策 T5 明确选了「纯文本渲染」，理由（`marked` 输出未净化 + WebView 的 localStorage 里是全部课程数据）依然成立 | 本轮要渲染 markdown，**安全边界必须换实现方式，而不是被删掉** |
| `marked@18.0.12` 已在依赖里（`app/features/substitute-management/export.ts` 用它）；仓库**没有** DOMPurify | 可以零新增依赖拿到 token 流；不要引 DOMPurify + `dangerouslySetInnerHTML` |

## 功能需求

### F1 节流记账：成功才消耗窗口

- 「上次检查」的时间戳语义改为**上一次成功拿到结果的时间**：只在请求成功（HTTP 2xx、JSON 可解析、顶层是数组）时更新。
  **有无新版本、是否被通道或「跳过此版本」过滤掉，都算成功**。
- 请求失败（网络错误、403/429 限流、5xx、响应结构不符）→ **不更新**该时间戳，所以下一次回到前台会立刻重试（用户口径）。
- 为避免「断网 / 被限流时来回切前台」把匿名额度打光（spec 既有约束：60 次/小时），失败后给一个**短冷却（60 秒）**：
  冷却期内不发起新的检查。冷却时长不作为用户可选项暴露。
- **重入保护**：一次检查还在进行中时，新的触发不重复发起请求。
- 手动检查仍然绕过间隔与冷却（用户明确点了按钮就要有反应）。
- 系统时间被改到未来时（时间戳大于当前时刻）不得把检查永久卡死。

### F2 间隔档位与存量提升

- 档位：`每次启动` / **`1 小时`（新的默认）** / `1 天` / `3 天` / `7 天`。
  `每次启动` 语义不变：每次冷启动与每次回到前台都放行（但仍受失败冷却与重入约束）。

  （2026-09-28 评审门确认：**保留**这一档，共 5 档；存量 `launch` 原样保留，不需要迁移。）
- **存量提升**（否则本机 `interval:"1d"` 的设备修不好）：升级后，若存储里是旧默认 `1d` 且**从未被用户手动改过间隔**，
  一次性提升为 `1h`；用户显式选过的档位（含手动选过 `1d`）保持不动。存储里没有该字段的设备直接拿新默认。
- 存储里出现不认识的值仍逐字段回落默认（既有规则不变）。

### F3 更新说明按 markdown 渲染

- release 正文（远端内容）按 markdown 渲染，至少支持：
  标题、段落、无序/有序列表（含嵌套）、粗体、斜体、删除线、行内代码、围栏代码块（原样展示、不执行）、链接、引用、分隔线、换行。
- **安全边界（替代原来的「纯文本」手段）**：
  - 解析结果**只经过 token → React 元素的映射**：任何路径都不得使用 `dangerouslySetInnerHTML`，
    不得把远端字符串拼进 HTML；
  - 原始 HTML（`<script>`、`<img onerror=…>`、任意标签）**按纯文本展示**，不产生元素；
  - 图片**不渲染**（不加载任何远端资源），退化成它的替代文本；
  - 链接只有 `http:` / `https:` 才生成 `<a>`，其它协议（`javascript:` / `data:` 等）退化成纯文本；外链带 `rel="noreferrer"`。
- 排版沿用模态框现状（限高可滚动、`text-sm leading-6`、`bg-muted/30`），不引入新字体与依赖。
- 正文 trim 后为空时仍给「本次发布没有填写更新说明。」
- 版本号、`当前版本 → 新版本`、通道标签与三个按钮的展示不变。
- 已知取舍（不是缺陷）：表格与图片**故意降级**为文本；更新说明里不会出现任何来自远端的富媒体。

## 约束与不做的事

- **不新增 npm 依赖**：只用已在依赖里的 `marked`。
- 平台范围仍是**仅 Android 原生**（`isAndroidApp()`）；浏览器 / PWA 行为不变。
- 不改动：通知与权限语义、通道判定与一次性播种、`skippedVersion` 语义、下载跳转的 URL 白名单、设置卡片的行结构。
- 判定逻辑继续保持「纯函数 + vitest」的既有风格：本轮新增的调度判定与 markdown 映射都必须能被单测钉住。
- 本轮不做模拟器真机验收（用户口径），真机相关条目只进残余风险，不作为验收门槛。
- 不新增网络请求目标；失败保持静默（不打扰用户）。

## 验收清单

**单测（`pnpm test`）**

- [ ] 间隔换算：`1h` = 3600000ms；`1d` / `3d` / `7d` 不变；`launch` 仍为 0；`DEFAULT_CHECK_INTERVAL` 为 `1h`；
      `CHECK_INTERVALS` 含全部档位且顺序稳定。
- [ ] 调度判定（纯函数）：
  - 从未检查过 → 放行；
  - 距上次**成功**不足间隔 → 不放行；超过间隔 → 放行；
  - **上次是失败**：距失败尝试不足冷却 → 不放行；超过冷却 → 放行（即使距上次成功还很近）；
  - `每次启动` 档刚成功过也放行，但仍受失败冷却约束；
  - 时间戳大于当前时刻（改过系统时间）→ 放行，不永久卡死；
  - 手动检查忽略间隔与冷却；
  - 检查进行中 → 不放行；
  - 不认识 / 越界的存储值 → 回落默认。
- [ ] 存量提升：无「改过间隔」标记 + `1d` → `1h`；有标记 + `1d` → 保持 `1d`；
      `launch` / `3d` / `7d`（无论有无标记）→ 保持；字段缺失 → 默认 `1h`；非法值 → 默认 `1h`；提升只发生一次。
- [ ] 成功才记账：network / rate-limited / invalid 三种失败原因都不会更新「上次成功」时间戳；成功（含无新版本、含被通道过滤、含被跳过）会更新。
- [ ] markdown 渲染（`renderToStaticMarkup` 断言）：
  - `ClassTrack Android **1.0.18-beta**` + `## 本次改动` + `- a` + `- b` → 出现强调元素与列表项，文本完整，
    且不出现字面量 `**` / `##`；
  - `` `code` `` → 行内代码元素；围栏代码块 → 原样文本（不高亮、不执行）；
  - `[x](https://github.com/Love-wmh/ClassTrack/releases/tag/v1.2.0)` → `<a href="https://…">` 且带 `rel="noreferrer"`；
  - `[x](javascript:alert(1))`、`[x](data:text/html,…)` → **不生成 `<a>`**，文本仍可读；
  - `<script>alert(1)</script>`、`<img src=x onerror=alert(1)>` → 结果里**不出现** `<script` / `<img` / `onerror`，只剩可读文本；
  - 表格语法与图片语法 → 不出现 `<table>` / `<img>`，按文本降级展示；
  - 未知 token（模拟 marked 升级）→ 不抛错、不丢文本；
  - 空正文 / 全空白 → 「本次发布没有填写更新说明。」
- [ ] 静态检查：`grep -rn "dangerouslySetInnerHTML=" app/` 全仓库 **0 命中**（只看「被用到」的形态；
      源码与 spec 里出现的裸标识都只允许出现在「禁止这么做」的说明文字里）。
- [ ] 「跳过此版本」仍只抑制自动提示：自动检查判不出候选、手动检查仍能判出（既有用例保持通过）。

**门禁**

- [ ] `pnpm typecheck`、`pnpm test`、`pnpm lint`、`pnpm format:check`、`pnpm build` 全过。

**已知取舍（不作为验收门槛，写进残余风险）**

- 节流仍在：新版本发布后，最早要等到「上次成功检查 + 间隔」才会被自动提示。默认 1 小时；想立刻发现可设为「每次启动」。
- 失败后 60 秒冷却期内切前台不会重试——这是为匿名限流额度付出的代价。
- 存量设备会经历一次「1 天 → 1 小时」的静默提升（无法区分「显式选过 1 天」与「一直是旧默认」）。
- markdown 只渲染白名单语法；表格 / 图片是故意降级。
