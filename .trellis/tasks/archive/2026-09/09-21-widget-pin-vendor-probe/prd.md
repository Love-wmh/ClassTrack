# 桌面卡片加桌：按厂商探测 pin 能力 + 降级引导（只覆盖最新系统）

> 调研依据 [research.md](./research.md) · 技术设计 [design.md](./design.md) · 执行计划 [implement.md](./implement.md)

## Goal

「应用内一键添加到桌面」在本 App 现有的真机上**从来没能成功过一次**（PKR110 / ColorOS / Android 16：launcher 起了确认页却从不置前，且不发确认回调）。本轮把这块从「一种实现赌所有 launcher」改成**按厂商分诊**：

1. **探测**：把「能不能加」从「问系统」（不可靠）改为**观察行为**（探针 + 确认回调 + 实例差集复核）；
2. **降级引导**：把「加不上」的原因说清楚，并给出**该厂商上确实可用**的手动路径（四家入口名与层级各不相同）；
3. **范围**：只覆盖**最新系统**（Android 14 / API 34 起 + 品牌命中）。老系统不碰，鸿蒙 NEXT 不碰。

成功的样子：同一个按钮，在支持的一键添加的设备上照旧成功；在四家的最新系统上，**无论能不能一键加**，用户都能在 2–10 秒内拿到一句正确的下一步，并能按该厂商的真实入口自己加完。

## 背景与现场约束

| 事实（来源见 [research.md](./research.md)） | 后果 |
|---|---|
| 公开 API 里**没有**「探测 pin 是否可用」的手段；`isRequestPinAppWidgetSupported()` 只表示 launcher 声明过支持，部分 ROM 恒真 | 只能做**行为探测**，不能做前置询问 |
| `requestPinAppWidget` 的第三个参数（PendingIntent）**成功才触发**；华为/荣耀类**根本不触发** | 只认回调的实现在这些设备上会**永远判失败**，即使卡片真的加上了 |
| 小米未开「创建桌面快捷方式」权限时 pin **静默失败**；且小米小部件中心只展示应用商店正式版的小部件 | 小米上需要权限引导；且因为我们是 CI/beta 包，小米上必须指向「**安卓小部件**」入口 |
| 四家的手动添加入口名与层级都不同（小部件 / 卡片→搜索 / 组件→应用挂件 / 服务卡片→窗口小工具），且**只有 OPPO 没有任何零审核的应用内添加能力** | 既有那句通用的「长按桌面空白处 → 小工具 → …」四家上都指错路；OPPO 只能走手动引导 |
| vivo 不接入原子组件 SDK 并审核上架时，pin **无任何效果** | vivo 上「一键添加」应如实降级为引导，不能让用户点完等 10 秒 |
| 小米官方文档给了 `extras(addType=appWidgetDetail)` 打开小部件中心详情页的公开能力 | 小米上多一条「优先尝试」路径（需真机验证对未上架原生 widget 是否生效） |
| 本仓库 `targetSdk=36` / `minSdk=24`，`PinAttempt` / `PinAttemptState` / `WidgetPinBaseline` / `WidgetPinResult` 已就位 | 新增探测只需在此基础上补一条「无回调复核」分支，不重写链路 |

## 术语

- **pin**：`AppWidgetManager.requestPinAppWidget(provider, extras, successCallback)`，即「从应用内请求把卡片加到桌面」。
- **厂商族（vendor family）**：小米 / OPPO / vivo / 荣耀 / 其他。**只用于选文案与引导路径**，不用于判断能力。
- **最新系统（modern）**：`Build.VERSION.SDK_INT >= 34`（Android 14）**且**厂商族不是「其他」。
- **无回调复核**：等待窗口结束后，用「请求前实例集合 ↔ 现在实例集合」的差集判断是否真的加上了。

## Requirements

### R1 厂商族识别：纯函数，只用于选文案

- 新增纯逻辑 `WidgetVendorFamily`：由 `Build.MANUFACTURER` / `Build.BRAND` 字符串判定厂商族。
- 判定必须**大小写不敏感**、对 `null`/空串安全、对未识别字符串回退 `OTHER`（不得抛异常）。
- 厂商族**只允许**影响：手动引导文案、小米专属 extras 与权限提示是否启用、vivo 是否出现「去组件库添加」按钮。
- **严禁**用厂商族直接断言「支持 / 不支持 pin」——那是行为探测的结论（见 D3）。

### R2 「最新系统」判定：版本 + 品牌双条件

- 新增纯函数 `WidgetVendorSupport.isModern(sdkInt, family)`：`sdkInt >= 34 && family != OTHER`。
- 老系统（MIUI 13/14、realme UI 3/4、Funtouch OS 13 等）与未识别厂商：**一律走通用引导**，不出现任何厂商专属话术。
- 门槛写成常量并带注释说明来源（HyperOS 1 / ColorOS 14 / OriginOS 4 / MagicOS 8 起为 Android 14+），便于后续上调。

### R3 能力探测改为三段式（含新增的「无回调复核」）

在既有「快探针（约 2 秒）+ 确认回调 + 超时兜底（10 秒）」之上，**新增第三段**：

- **T3 无回调复核**：等待窗口结束时，若确认回调始终没到，再比对一次实例集合：
  - 请求前实例集合（`WidgetPinBaseline`）**仍有效**、且现在出现了**新实例** → 判定为**已添加**（`added`），而不是「未完成」。
  - 基线不可用（`null`，即没记录或已超时）→ **不得**据此判成功，必须回落到「未确认」。
  - 没有新实例 → 回落「未确认」。
- 复核结论与既有 `PinAttempt` 探针**不得互相覆盖**：探针已给出「系统没有弹出确认界面」时，若复核命中成功，成功优先（真的加上了就不该说没弹出）。
- 复核只能读实例**数量与 id 集合**，不得读取任何课程内容。

### R4 无回调复核必须如实措辞

- 复核命中时的文案不得写成「系统已确认」——我们只知道**桌面上多了一张课表卡片**，不知道是谁放的。
- 文案口径：「检测到桌面上新增了一张课表卡片。」并在需要时补一句「如果不是你刚添加的，请忽略。」
- 「已添加」这个状态在复核命中时同样可以点亮对应那张预设卡（用户的心智是「我刚加了它」），但提示语必须与回调命中可区分（回调命中不额外解释；复核命中带上面那句限定）。

### R5 厂商专属手动引导

- 现有 `WIDGET_PIN_MANUAL_STEPS`（单一通用文案）改为**按厂商取文案**，并在面板底部常驻（沿用既有行为）。
- 五套文案（内容以 [research.md §4](./research.md) 为准，均为两处独立来源）：
  | 厂商族 | 路径关键节点 |
  |---|---|
  | 小米 | 双指捏合 → 「小部件」→ 中心点「搜索」→「**安卓小部件**」→ 找到课表 → 拖到桌面 → 右上角「√」 |
  | OPPO | 长按桌面空白处 → 「卡片」→ **直接搜索「课表」**（搜不到再滑到底找「插件」）→ 找到课表并添加 |
  | vivo | 长按桌面空白处 → 「组件」→ 底部「**应用挂件**」→ 下滑找到课表 |
  | 荣耀 | 双指捏合 → 「服务卡片 / 桌面卡片」→ 滑到底 → 「**窗口小工具 / 经典小工具**」→ 找到课表 |
  | 其他 / 老系统 | 长按桌面空白处 → 「小工具 / 小组件」→ 找到课表（既有的通用文案） |
- 文案里**仍要指名两档尺寸**（`3×2` / `1×2`）——尺寸清单继续从预设表生成，避免手写漂移。
- 小米以外的三家：短语里不得出现我们无法保证的词（例如荣耀的入口名在两代系统间不同，必须写成「服务卡片 / 桌面卡片」这种并列）。
- **空间不足提示**：荣耀/华为类不会自动新建一页，只提示「当前页面空间不足」→ 这四家的引导里统一补一句「当前页放不下时，先滑到有空位的页面」。
- 荣耀的专属部分**只有文案**（D10）：入口名换成「服务卡片 / 桌面卡片」→「窗口小工具 / 经典小工具」；不加 extras、不加任何提示、不影响探测。

### R6 小米：先用官方接口探测，再打开「小部件中心」详情页（零审核）

- 在小米族 + 最新系统上，pin 请求的 `extras` **额外**携带：
  - `addType = "appWidgetDetail"`
  - `widgetName = "<包名>/<该档 provider 的完整类名>"`
- 该 extras **不得替代**标准 pin：仍然照传 `successCallback`、仍然记基线、仍然走完整三段探测（因为该能力对「未上架审核的原生 widget」是否生效是**未知的**，见 V1）。
- 若真机验证该能力不生效（V1 为否），必须能**只删这一处**回退到标准 pin，不牵连其他逻辑。
- 不得为此申请「小米小部件」标识：那会让组件从原生组件池消失，且需要独立进程与审核上架（D6）。

- **前置探测（官方接口，零审核）**：调用小米官方 ContentProvider 的两个方法，结果**决定是否启用** R6 这条路：
  - `ContentResolver.call(Uri.parse("content://com.miui.personalassistant.widget.external"), "isMiuiWidgetSupported", null, null)`
  - 同 URI，`"isMiuiWidgetDetailPageSupported"` → 官方原文：「部分机型支持小米Widget…但**不支持调起小米Widget 详情页**。这部分机型添加小部件的方式与旧版系统一致。」
  - 探测失败（Provider 不存在 / 抛异常 / 返回 null）一律按「不支持」处理，**不得**因此崩溃或阻塞 pin。
  - 探测结果按进程缓存一次即可，不必每次点按都问。
- **`android:label` 相同 → 详情页聚合**（官方原文）：我们多档 provider 若共用同一 label，会在小米详情页里被聚合成「同一功能的不同尺寸」，用户在一个页面里就能选全部尺寸。这条要在 provider 标签的既有约束下确认可行，不得为此改名破坏存量实例。
### R7 小米：把「创建桌面快捷方式」权限讲清楚，并可跳转

- 在小米族 + 最新系统上，面板里出现一条**独立**的提示：「小米手机需要为课表打开『创建桌面快捷方式』权限，否则一键添加不会生效。」
- 提示带一个可点按钮，点击后：
  1. 先尝试跳 MIUI 权限页（`miui.intent.action.APP_PERM_EDITOR` → `com.miui.securitycenter/...PermissionsEditorActivity`，带 `extra_pkgname`）；
  2. 抛 `ActivityNotFoundException`（或任何 `RuntimeException`）时回退到系统「应用详情页」（`Settings.ACTION_APPLICATION_DETAILS_SETTINGS`）；
  3. 两者都失败时**什么都不做**，只记一条诊断，不得崩溃、不得弹红错。
- 这不是能力探测，只是**导航**：跳转失败不影响任何功能路径；文案里不得声称「一键跳转一定能到那个开关」。
- 权限是否开启**不做程序化检测**（公开 API 无 `OP_REQUEST_PIN_SHORTCUT`，见 research.md §1 的反例校验）→ 永远只提示，不判断。

### R8 跨层一致性与门禁

- 新增的原生纯逻辑（厂商族、modern 判定）必须有 JUnit 覆盖；Web 侧新增的文案映射必须有 vitest 覆盖。
- 既有跨层约束不变：Web 预设表 ↔ `WidgetPreset.java` 白名单 ↔ `WidgetProviderRegistry.java` ↔ 清单 ↔ `widget_info_*.xml` ↔ 预览资产，必须继续由 `widgetPinPresets.test.ts` / `check-android-assets.js` 守住。
- `widgetPinPresets.test.ts` 新增断言：**每个厂商族都有一条手动引导文案**，且**不得**再存在单一通用常量被直接引用。
- 门禁：`pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm android:check-assets`、`./android/gradlew -p android testDebugUnitTest` 全绿。

### R9 vivo：一键跳到「原子组件库详情页」

- 在 vivo 族 + modern 上，面板除常驻的手动步骤外，提供「去组件库添加」按钮，点击后按 vivo 官方适配指南（research §3.4）跳转：
  - 权限：清单声明 `<uses-permission android:name="com.bbk.launcher2.permission.JUMP_ORIGIN" />`
  - Intent：`setPackage("com.bbk.launcher2")` + `setData(Uri.parse("vivo://com.bbk.launcher2/origin?..."))`，参数含 `pkg` / `classname` / `comType=0` / `locType=1`
- **参数名以官方示例代码为准**：vivo 同一节正文写 `cmpType`、示例代码写 `comType`（**官方文档自相矛盾**）→ 参数名必须集中成一个常量，便于真机验证后一处改完。
- fail-safe 与 R7 同规格：解析不到 / `startActivity` 抛 `RuntimeException` → 什么都不做，只记一条诊断；按钮文案不得承诺「一定能打开」。
- 该按钮**不替代**手动步骤：手动步骤仍然常驻（未上架时跳转很可能无效）。
- 文案写成「打开组件库」，**不得**写成「这里一定能看到课表」——未上架审核的组件是否被组件库展示是未知的（V5）。

## 产品决策（本轮敲定 + 被否方案）

| # | 决策 | 备选与被否原因 |
|---|---|---|
| D1 | 「最新系统」= `SDK_INT >= 34` **且** 品牌命中 | 「只按品牌不限版本」被否：会在 MIUI 13/14 上给出 HyperOS 的入口话术，比不给还糟；「品牌 + 解析厂商版本号」被否：依赖 `ro.mi.os.version.name` 这类字段，跨版本易碎 |
| D2 | 无回调时用**实例差集复核**，命中即判「已添加」 | 「只认回调」被否：华为/荣耀类会永远显示未完成；「差集只用于改文案」被否：用户已经看到卡片在桌面上，还说「未完成」是自相矛盾 |
| D3 | 能力结论**只**来自行为探测；厂商族只选文案 | 「按品牌硬编码能力表」被否：社区矩阵说 OPPO「弹确认框」，我们的真机是「起了不置前」，同家不同版本会漂移 |
| D4 | 不做「桌面快捷方式权限」的程序化检测（不用反射 AppOps） | 「反射调 `MiuiAppOpsManager` + 硬编码操作码」被否：属私有 API 直连、随版本失效，且公开 SDK 连 `OP_REQUEST_PIN_SHORTCUT` 都没有（research.md §1） |
| D5 | 小米的 `addType=appWidgetDetail` 纳入，但**并列**于标准 pin，不做替代 | 「替代标准 pin」被否：该能力对未上架原生 widget 是否生效未知，替代会让小米上的成功路径更窄 |
| D6 | 不申请小米小部件标识，也不申请荣耀 `honorcard` 标识 | 「申请小米标识」被否：会让组件从原生组件池消失 + 需要独立进程 + 需审核上架，与本轮范围不符 |
| D7 | vivo 不做 SDK 接入，只做引导 | 「接入原子组件 SDK」被否：需要平台申请与审核上架，是独立产品决策，不是本轮的适配工作 |
| D8 | 荣耀入口文案写成「服务卡片 / 桌面卡片」并列 | 「只写服务卡片」被否：荣耀新旧两代帮助文档用词不同，并列写法更抗漂移 |
| D9 | 鸿蒙 NEXT 不在本轮 | 纯鸿蒙无 `AppWidget` 体系；登记为后续独立的鸿蒙原生版任务 |
| D10 | 荣耀**只换入口命名文案**，不做任何能力适配 | 「荣耀完全归入通用族」被否：荣耀的入口叫「服务卡片 / 窗口小工具」，通用句里的「小工具」会让用户在荣耀上找不到入口；「给荣耀加 extras / 提示」被否：荣耀官方文档明确「遵循 Google 原生 widget 开发规范」，没有可加的厂商能力（research §3.2） |
| D11 | vivo 纳入「跳转原子组件库详情页」（官方文档化能力） | 「只给纯文案」被否：官方给了跳转能力，能把用户直接送到能添加的地方，比让用户自己找「组件 → 应用挂件」可靠；「先记录不实现」被否：fail-safe 成本极低（跳不动就退回文案） |
| D12 | OPPO **只做手动引导**（面板不给任何按钮），路径按产品口径写成「长按桌面 → 『卡片』→ **直接搜索课表**」 | 「为 OPPO 破例走插件卡」被否：需授权码 + 商务审批，与「一切需要审核的都不要」的口径冲突；统一写「滚到最底找插件」被否：搜索更快且用户口径明确 |
| D13 | 小米的「探测 + 详情页 extras」与 vivo 的「组件库跳转」**两条都纳入** | 「只纳入小米」被否：vivo 跳转的官方前置条件只有「声明权限 + 显式 intent」，同样是零审核；「两条都不纳入」被否：那就退化成纯文案，放弃了官方给的能力 |

## Acceptance Criteria

- [ ] A1 厂商族识别：`WidgetVendorFamily` 有 JUnit 覆盖（四家 + 未识别 + `null`/空串 + 大小写混合），未识别一律 `OTHER`；Web 侧同语义的映射有 vitest 覆盖，两侧对同一输入的结论一致（跨层测试）。
- [ ] A2 modern 判定：`SDK_INT 33` / `34` 边界有 JUnit 覆盖；`SDK_INT <= 33` 时**任何**厂商专属话术都不出现（面板文案与通用族逐字相同）。
- [ ] A3 无回调复核：`WidgetPinTargets`（或新纯函数）的「无回调 + 新实例 → added」「无回调 + 无新实例 → 未确认」「基线为 `null` → 绝不判成功」三条各有单测；复核命中时**探针结论被成功覆盖**这条也有单测。
- [ ] A4 面板文案：四家 + 通用共五条手动路径，各自的**关键节点**（小米「安卓小部件」、OPPO「卡片」+「搜索」、vivo「应用挂件」、荣耀「窗口小工具」）都出现在文案里；四家文案都含「先滑到有空位的页面」的补充说明（空间不足）。
- [ ] A5 复核命中与回调命中的提示语**可区分**：vitest 断言复核命中时文案含「如果不是你刚添加的」，回调命中时不含。
- [ ] A6 小米 extras：单测断言小米族 + modern 时 `extras` 含 `addType=appWidgetDetail` 与形如 `包名/类名` 的 `widgetName`；非小米族**不含**这两个键；标准 extras（`OPTION_APPWIDGET_MIN_WIDTH/HEIGHT`）在所有情况下仍在。
- [ ] A7 小米权限引导：出现在小米族 + modern 的面板上（且**不**出现在其他族）；点击分支的三条路径（MIUI 页成功 / 回退应用详情页 / 都失败）各有单测或可注入的判决函数覆盖，且都不抛异常。
