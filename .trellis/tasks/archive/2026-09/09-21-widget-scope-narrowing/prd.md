# 小工具：只维护 3×2「接下来」+ 1×2「紧凑」两档，其余尺寸收起入口

## Goal

把桌面小工具的**维护面从五档尺寸收缩到两档核心档**，其余档位只收起入口、不删代码：

| 档位 | 拾取器标签 | targetCell（宽×高） | 样式 |
|---|---|---|---|
| 3×2 | `课表` | 3 × 2 | 接下来（`NEXT_UP`） |
| 1×2 | `课表` | 1 × 2 | 紧凑（`COMPACT`） |

两档在拾取器里**同名**（就叫应用名「课表」）：用户按 launcher 自己打出的跨度标签区分（见 R8）。

产品口径（2026-09-21，用户）：**一切核心围绕「接下来 + 高2宽3」**，再留一个「高2宽1 紧凑」，其余入口收起来；
「自动」「双栏」两个选项不要；其他入口收到二级菜单。

尺寸方向统一按**宽×高**书写，与既有代码/资源一致：`3×2` = `targetCellWidth=3` / `targetCellHeight=2`
（= 用户说的「高2宽3」）；`1×2` = 用户说的「高2宽1」。用户口语用「高×宽」，本任务所有 ID、标签、文件名一律用「宽×高」。

## 背景与现场约束

| 事实（沿用既有结论） | 后果 |
|---|---|
| 拾取器里的尺寸标签来自 provider 自己声明的 `targetCell*`，pin 的 extras 会被 launcher 忽略 | 想只让拾取器留两档，唯一手段是**启用/禁用 provider 组件** |
| 一个 `GlanceAppWidget` 可被多个 receiver 共享 | 新增两档不必复制渲染逻辑（沿用既有做法） |
| 禁用 receiver 组件会把它从拾取器移除；该 provider 不再收到 `APPWIDGET_UPDATE`；应用更新时其存量实例可能被系统清除 | 桌面上已有的 2×2 / 2×3 / 4×2 / 4×3 / 6×3 实例会**冻结**（本轮明确接受，见 D3） |
| `requestPinAppWidget` 在 ColorOS 上会被静默丢弃 | 应用内面板仍只做「请求 + 诚实反馈」，可靠路径是系统拾取器 |
| 已有 3×2 的真机量测值（276×210dp，09-20 实测），但没有 1×2 的量测值 | 1×2 的标定样本先用估算值落地，真机量测后校准（A6） |

## Requirements

### R1 只维护两档尺寸（新增 3×2 与 1×2 两个 provider）

- 新增 `Cell3x2WidgetReceiver`（3×2，默认样式「接下来」）与 `Cell1x2WidgetReceiver`（1×2，默认样式「紧凑」）：
  各自独立的 `widget_info_*.xml`（`targetCellWidth/Height`、`configure`、`updatePeriodMillis`、
  `previewLayout` + `previewImage`）、独立 `android:label`、独立拾取器预览资产。
- 两个新 provider 与既有 5 个共用同一个 `ClassTrackWidget` 渲染入口（不复制渲染逻辑）。
- **尺寸仍可自由拖动**：两个新 provider 的 `resizeMode` 保持 `horizontal|vertical`；样式不再随尺寸变化（见 R3）。
- 1×2 provider 的 `minWidth` 要低于"一列宽"，否则旧 launcher 会把它当成两列（见 design D7）。

### R2 其余五档：收起入口，不删代码

- 应用启动时**一律禁用**其余五个 receiver 组件（2×2 / 2×3 / 4×2 / 4×3 / 6×3），使系统拾取器里只剩两档。
  禁用必须**幂等**，且每次启动都重新收敛（重装 / 清数据后仍生效）。
- 这五个 receiver 的类、`widget_info_*.xml`、预览资产、原生预设表条目、清单条目**本轮一律保留**
  —— `ClassTrackWidgetReceiver` 这个旧类名尤其不能动（改名会让既有实例失效）。
- 明确代价（已接受，见 D3）：桌面上已放置的这些尺寸实例会停止刷新；应用更新时可能被系统清除。
  本轮**不做迁移、不做用户提示**。
- 漏档即失败：禁用清单必须与「非维护档」集合严格一一对应（漏一个，拾取器里就会多出一条）。

### R3 「自动（按尺寸）」与「双栏」从 UI 收起

- 原生配置页不再提供「自动（按尺寸）」与「双栏」两个选项。
- `LayoutStyle.AUTO` 与 `WideLayout.TWO_COLUMN` 的**枚举与解析保留**：存量实例存过 `auto` / `two_column`，
  读完必须能落成一个可渲染的配置（回落到默认），不抛异常、不改写存储值。
- **不再按尺寸切换样式**：删掉「按当前尺寸最近邻匹配预设」这条路径。
  实例未显式配置时的解析结果 = **该实例 provider 那档预设的样式**；预设缺失时回退「接下来」。
- 默认样式由「自动」改为「接下来」（`NEXT_UP`）。

### R4 pin 即带样式（预设就是用户的显式选择）

- 应用内点某张卡 pin 时，必须把**该预设的样式**写进新实例：3×2 → 接下来、1×2 → 紧凑。
  （现状写的是 `AUTO`，依赖尺寸匹配；匹配被删掉后必须显式写，否则 1×2 会渲染成「接下来」。）
- 配置页预填仍要消费一次性槽位（`WidgetPendingPreset`），让放置时看到的选中项与点击的卡一致。

### R5 应用内「添加到桌面」面板只留两张维护卡

- 一级只有两张卡：`接下来 3×2`、`紧凑 1×2`；卡片名与拾取器标签逐字对应（`课表 · ` + 卡片名）。
- 其余五档**不下发**到 Web 侧预设表：provider 被禁用后连 pin 都放不下，列出来只会是死卡。
- 面板底部常驻的手动步骤文案改为按这两档指名（尺寸清单仍从预设表生成）。
- 面板文案继续不承诺尺寸（「格子大小以桌面实际放下为准，可以自己拖动调整」）。

### R6 原生配置页做二级菜单

- 一级只留「接下来」（含它的实时预览）。
- 默认折叠的「更多设置」二级区收录：其余布局样式（全天课表 / 紧凑，含各自预览）、「已上完的课」策略、
  「大格子表现」剩下两项（跟随尺寸 / 信息加密；「双栏」已按 R3 收起）。
- 二级区默认折叠**不得让已有配置看起来丢了**：进页面时若实例选了二级区里的某项，二级区要自动展开并显示选中项。
- 「已上完的课」与「大格子表现」对「紧凑」不生效的灰显说明沿用既有行为。

### R7 跨层与资产同步

- 拾取器标签、Web 预设表、`WidgetProviderRegistry.java`、清单、7 份 `widget_info_*.xml`、
  预览资产（两个新档各一份 previewLayout + previewImage）必须同步。
- 跨层测试与 `check-android-assets` 的断言按「7 档 = 2 维护档 + 5 收起档」更新，
  并**新增一条断言**：非维护档集合与运行时禁用清单严格一致。

### R8 拾取器标签收敛为应用名（2026-09-21 用户追加）

- 两档的 `android:label` 都是「课表」：**不带样式、也不带尺寸**。
- 理由（用户口径）：launcher 会在标签下方自己打出它算出的跨度（如「3 × 2」「2 × 2」），名字里再写一个尺寸就会互相矛盾；
  而那个跨度标签本来就不受我们控制（实测 launcher 取 `max(targetCell, minWidth/minHeight 推出的跨度)`，见 D11）。
- 「接下来 / 紧凑」这种摆法名只属于应用内面板（那里必须能区分），卡片名与 provider 标签不再逐字对应。

### R9「紧凑」要列主课之后的课，且任何地方都不许省掉教室（2026-09-21 用户追加）

- 1×2 是竖长的窄卡，原来只画「主课 + 一行计数」，下方留一整块空白。改成：主课 → 计数 → **主课之后的课**。
- 「主课之后的课」= 行序列里 hero 之后的行（hero = 正在上的那节；没有正在上的就是第一节还没上的那节）。
  因此已上完的行永远不会出现在紧凑样式里，「今天已上完的课」这个选项对它始终无效果 —— 配置页那句灰显说明按这个原因改写。
- **教室不能被省掉**：任何显示某节课的地方都必须能看见教室。
  - 窄格里一行写「14:00 - 15:35 · C305」会被裁成「14:00 - …」，所以紧凑样式的 hero 明细拆成两行（时间 / 教室）；
  - 课程行在窄格里不能用「时间独占一列 + 课名 + 教室靠右」的形态（课名只剩三十几 dp），改用窄卡形态：课名一行、「时间 · 教室」一行。

## 产品决策（本轮敲定 + 被否方案）

| # | 决策 | 备选与被否原因 |
|---|---|---|
| D1 | 维护 3×2（接下来）+ 1×2（紧凑）两档 | 「只维护 3×2 一档」被否：用户要再留一个「高2宽1 紧凑」 |
| D2 | 「二级菜单」只做在原生配置页；应用内面板只留两张卡，其余五档不下发 | 「面板里也列五档并置灰」被否：禁用的 provider 点了也不能用，是死卡 |
| D3 | 其余五档一律禁用 receiver | 「有存量实例就不禁用」被否：用户选择一律禁用；存量实例冻结的代价已知并接受 |
| D4 | `AUTO` / `TWO_COLUMN` 只从 UI 收起，枚举与解析保留 | 「连枚举一起删」被否：存量存储值要能继续读，且不留解析异常面 |
| D5 | 原生预设表保留全部 7 档；Web 预设表只留 2 档 | 原生侧要服务存量实例的归属校验与样式回退；Web 侧留下死数据只会误导下一个改的人 |
| D6 | 「已上完的课」等非核心选项进二级区，而不是删除 | 用户口径是「收到二级菜单」，不是「删掉」 |
| D7 | 两档的拾取器标签都叫「课表」（不带样式、不带尺寸） | 「课表 · 接下来 3×2」被否：用户口径「尺寸不要写在小组件名字上」，随后又要求「名字只保留课表」 |
| D8 | 「紧凑」列主课之后的课；教室在任何地方都不省 | 「紧凑 = 只有一节主课」被否：竖长窄卡下方一整块空白（用户截图指出） |
| D9 | 紧凑样式的课程行用窄卡形态（课名一行、「时间 · 教室」一行） | 「沿用时间列的宽格行形态」被否：82~105dp 格里课名只剩三十几 dp，四个字的课名被裁成「线性代…」 |
| D10 | 预览 mock 的文本一律单行、文案必须与运行期一致 | 「mock 自由发挥」被否：mock 曾写「正在进行 · 第 3-4 节」（运行期没有这句），且窄格里折成五行、比真机还难看 |
| D11 | 1×2 的 `minWidth` 定 60dp（低于一列宽） | 「90dp」被否：launcher 取 `max(targetCell, minWidth/minHeight 推出的跨度)`，90dp 会被它抬成「2 × 2」 |

## Acceptance Criteria

- [ ] A1 两档 provider 落地：`Cell3x2WidgetReceiver` / `Cell1x2WidgetReceiver` 各带自己的 metadata 与预览；
      清单共 7 条 `APPWIDGET_UPDATE` receiver；`ClassTrackWidgetReceiver` 旧类名仍在。
- [ ] A2 收起生效：应用启动后其余五个 receiver 处于禁用态（幂等，重复启动不反复写）；真机上系统拾取器只剩
      `课表 · 接下来 3×2` 与 `课表 · 紧凑 1×2` 两条。
- [ ] A3 样式不再随尺寸变：尺寸匹配路径删除；未配置实例解析为 provider 预设的样式，预设缺失回退「接下来」；
      存量 `auto` / `two_column` 的解析有单测覆盖。
- [ ] A4 pin 即带样式：pin 3×2 → 实例是「接下来」；pin 1×2 → 实例是「紧凑」（判决函数有单测）。
- [ ] A5 UI 收起：配置页一级只有「接下来」，二级「更多设置」默认折叠且含其余样式 / 已上完 / 大格子表现
      （页面里不存在「自动」与「双栏」两项）；应用内面板只有两张卡。
- [ ] A6 真机验收：两档从拾取器拖放成功且样式正确；拖动改尺寸不裁切、不空荡；1×2 实测尺寸回填标定样本与预览资产。
- [ ] A7 门禁全绿：`pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm android:check-assets`、
      `pnpm test:android-assets`、`./android/gradlew -p android testDebugUnitTest`。
- [ ] A8 spec 更新：`android-home-widget.md` 里「五个 provider」「AUTO 尺寸匹配」「双栏选项」等条目改为
      「两档维护 + 五档收起（运行时禁用）」的事实。
- [ ] A9 标签收敛：两档 `android:label` 均为「课表」；`strings.xml` 里维护档标签不含样式名与尺寸；
      跨层测试断言「标签恒为课表」且「面板卡片名可区分」。
- [ ] A10 紧凑内容：紧凑样式 = 主课（明细两行：时间 / 教室）+ 计数 + 主课之后的课；课程行是窄卡形态；
      hero 之后的判定有单测（正在进行 / 无正在进行 / 列明天 / 全天已上完四种）；两份 1×2 预览资产同步重跑。
- [ ] A11 预览诚实性：维护档的 `previewLayout` 单行文本都带 `maxLines=1`；`widget_preview_hero_label` 与运行期
      in-progress 文案一致；`--check` 模式可校验布局 mock 与生成结果一致。

## Out of scope

- 删除旧五档的类、metadata、预览资产与清单条目（本轮只收起，`ClassTrackWidgetReceiver` 只是被禁用）。
- 存量旧尺寸实例的迁移、冻结提示或兼容渲染。
- profile 页的小工具精度设置与快照同步链路（本轮不动）。
- iOS / 浏览器：面板本就只在 Android 原生渲染。
