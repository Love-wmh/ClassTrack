# 导入后使用引导：加桌引导 + 安卓导入方式收窄

## Goal

1. **导入成功后一次性引导用户把小工具加到桌面**，并明确提示「可以拖动改尺寸、换个档位试，找到最佳表现」。
   现状：导入成功只弹一个 toast + 关弹窗（`useImportFlow` 三条导入路径都是这样），应用里**没有任何导入后的后续引导**。
2. **安卓端的导入方式收窄**：只保留「应用内打开教务系统」+「导入已有数据（备份）」两张卡；
   天工（天津工业大学）没有原生适配器，选中它时提示「安卓暂不支持」并指路备份导入。

两件事都只在 Web 层（`app/**`），不动 Android 原生代码。

## 背景与现状事实

| 事实 | 后果 |
|---|---|
| 桌面小工具只在 Android 原生存在（`isNativeWidgetSnapshotAvailable()` = `getPlatform() === 'android'` 且插件已注册） | 加桌引导只在 Android 原生弹；浏览器 / PWA / iOS 弹出来是「指向不存在的功能」 |
| 加桌入口是课表页顶栏的 `WidgetPinEntry`（bottom Sheet，两档预设 `cell_3x2` / `cell_1x2`），内部 `Sheet` 目前是**非受控**的 | 引导想「一键直达并自动打开面板」必须先把它改成受控 |
| 当前 Sheet 描述只有一句「选一种摆法…格子大小以桌面实际放下为准，可以自己拖动调整」 | 「调尺寸找最佳表现」这条体验提示没有出现在任何引导位 |
| 应用内导入的返回值经 `CourseImportPlugin.open()` resolve 回主 WebView，`handleNativeImport` 是主壳里的成功路径 | 引导挂在这条成功路径上即可覆盖真实的原生导入 |
| 导入方式由 `ImportSchoolStep` 过滤（`native-webview` 仅当有原生适配器时出现），默认值在 `uiSlice.selectedImportMethod = 'parser'` | 安卓收窄必须在**策略层**解决（列表 + 默认值 + 切校收敛），不能只藏一张卡 |
| 天工（`tianjin-polytechnic-university`）没有原生适配器；`handleSchoolChange` 当前会把 `native-webview` 退回 `parser` | 安卓选天工会退到一个即将被隐藏的 `parser` 步骤 → 必须退到 `backup` |
| 备份导入（`backup`）是换设备恢复数据的唯一口子 | 安卓保留它；**不**保留书签脚本 / JSON 上传（用户口径见下方「口径确认记录」） |

## 口径确认记录（2026-09-22，用户）

1. 引导形态：**导入成功后弹一次性引导**（不是常驻卡片）。
2. 引导范围：**只在 Android 原生弹**。
3. 引导行动按钮：**直达课表页并自动打开加桌面板**。
4. 尺寸提示：**引导弹窗 + 加桌面板都写**。
5. 安卓导入方式：**应用内 + 备份**两张卡；天工提示「安卓暂不支持」。
   ⚠️ 用户原文里的「请使用 json 导入」是**表述失误**，本意是**「请使用备份导入」**；解析器（JSON 上传 / 书签脚本）在安卓端一律不出现在方式列表里。

## Requirements

### R1 导入成功后的一次性加桌引导（仅 Android 原生）

- **触发**：三条导入路径任一条成功（`handleNativeImport` / `handleParserImport` / `handleBackupImport`）后弹一次；
  在 Android 原生壳之外**完全不弹**（判定沿用 `isNativeWidgetSnapshotAvailable()`）。
- **内容**：一条「把课表放到桌面」的说明，至少讲清两点：
  1. 桌面卡片怎么加（课表页顶栏的「添加到桌面」，两档摆法各自适合什么）；
  2. **可以拖动卡片改尺寸**，同一档位下尺寸不同表现不同，试几个找到最舒服的（文案与面板复用同一份常量）。
- **主按钮「去添加」**：关闭引导 → 跳到课表页 → 自动打开加桌面板（Sheet）。
- **次按钮「知道了」**：只关闭，不做任何跳转。
- **只弹一次**：设备本地标记（独立 localStorage 键），不随备份迁移、不进 Zustand `persist` 的 `partialize`。
  读过之后**不再自动弹**（用户仍可从顶栏入口随时加桌）。
- 关闭方式（点关闭 / Esc / 主次按钮）都算「已读」，下次不再自动弹。
- 引导不得打断导入结果反馈：先出现原有的导入成功 toast，再出现引导。

### R2 加桌面板补「尺寸可调」提示

- 面板（Sheet）里补「可以拖动改尺寸 / 换个档位试」这条体验提示，文案与 R1 引导**同一份常量**（禁止两处各抄一份）。
- 面板不新增任何承诺：仍不得写出「一定按目标格子放好」这类不成立的说法（沿用既有口径）。
- 卡片名、两档预设、手动步骤文案**不改**（`widgetPinPresets.test.ts` 守着的契约保持不变）。

### R3 Android 导入方式收窄

- **平台判定**用「是不是 Android 客户端」（`Capacitor.getPlatform() === 'android'`），**不是**「插件是否注册」：
  天工没有适配器也必须进入收窄后的口径。
- Android 上「导入方式」列表 = `native-webview`（仅当所选学校有原生适配器）+ `backup`；
  `parser`（书签脚本 / JSON 上传）**不出现**。
- Android + 所选学校无原生适配器（天工）：列表只剩 `backup`，并在方式列表处显示一条提示
  「安卓暂不支持天津工业大学的应用内导入。请改用「导入已有数据」恢复课程表。」（2026-09-22 评审定稿，两句话，换行显示）
- **默认方式**按平台与学校联合决定，进入第 1 步即选中可用项：
  - Android + 有适配器 → `native-webview`
  - Android + 无适配器 → `backup`
  - 非 Android → 现状不变（`parser`）
- **切校收敛**：Android 上从天理切到天工（或反向）后，当前方式与步数必须收敛到新策略的合法值，
  不得停在 `parser` 的四步流程上，也不得停留在越界的步骤序号。
- **非 Android 行为零变化**：浏览器 / PWA / iOS 仍提供 `backup` / `parser` / （有插件时）`native-webview`，
  书签脚本与 JSON 上传路径、步骤数、默认值全部保持现状。

## 非目标

- 不做 iOS 端引导；不改 Android 原生代码、`strings.xml`、provider 注册表、pin 链路。
- 不做多步 tour / 高亮遮罩式引导；只做「一次性说明型弹窗 + 一个直达按钮」。
- 不给天津工业大学新增原生导入适配器（所以天工的安卓端确实没有应用内导入，这是产品口径）。
- **不**在安卓端提供 JSON 上传（用户口径修正后，安卓端解析器路径整体不出现在方式列表）。
- 不做「引导已读状态随备份迁移 / 多设备同步」；设备本地一次即止。

## Acceptance Criteria

| ID | 验收点 | 验证方式 |
|---|---|---|
| A1 | 策略纯函数：Android 有适配器 → `['native-webview','backup']` + 默认 `native-webview`；Android 无适配器 → `['backup']` + 默认 `backup` + 一条提示码；非 Android → 现状列表与默认 `parser` | vitest（`resolveImportMethodPolicy` 全矩阵） |
| A2 | 每个提示码都有非空文案（漏一个即红） | vitest（仿 `widgetPinPresets.test.ts` 的「每家一条非空文案」断言） |
| A3 | 引导「已读」判定：未读 / 已读 / localStorage 抛异常三种情况都不抛错，且只弹一次 | vitest（注入假 storage） |
| A4 | 导入成功后引导出现；Android 原生之外不出现 | 真机/模拟器（A7 的证据链）+ 静态渲染断言 |
| A5 | 「去添加」→ 课表页 + 面板自动展开；「知道了」→ 只关闭 | 单测（受控开关）+ 设备实测 |
| A6 | 面板与引导共享同一份尺寸提示常量，且该常量为非空、提到「尺寸」 | vitest（断言同一常量被两处引用） |
| A7 | 安卓端：天理看到「应用内 + 备份」，天工看到「备份 + 提示」，**没有**解析器卡；非安卓三张卡照旧 | 设备实测（`classtrack-android-webview-verify` 手法）+ 静态渲染断言 |
| A8 | 五项门禁全绿：`pnpm typecheck` / `pnpm lint` / `pnpm format:check` / `pnpm test` / `pnpm build` | 本地执行 |
| A9 | 规格同步：`native-course-import.md` 补「安卓端方式收窄」这条现行契约 | Phase 3.3 检查 diff |

## 风险与已知缺口

| 风险 | 说明 / 处置 |
|---|---|
| **天工安卓用户无法首次导入**（2026-09-22 评审**确认接受**的代价） | 收窄后安卓只剩应用内（天工没有）与备份导入，全新用户没有备份文件就导入不了。提示文案指路「导入已有数据」且不承诺「马上能用」；Phase 3.3 把这条写进规格作为已知限制（将来要支持天工，得加原生适配器，不是改前端） |
| 引导可能被用户跳过 | 「只弹一次」是刻意选择（不打扰）；顶栏 `WidgetPinEntry` 常驻入口是兜底路径，验收时确认它仍在 |
| 面板从非受控改受控可能影响现有 pin 交互 | 受控化只接管 `open`；pin / 轮询 / 模态状态机不动，回归靠 `widgetPinPresets.test.ts` + 设备实测一次加桌 |
| 引导与 toast 同时出现可能挤在一起 | 引导用 Dialog（打断式），toast 在上方；设备实测确认不遮挡关键按钮 |
| 设备实测依赖 Android 构建链（JDK 21 + SDK） | 若本机无法出 APK，记录为残余风险并在 `verification.md` 写明未验证项，不得写成「已验证」 |
