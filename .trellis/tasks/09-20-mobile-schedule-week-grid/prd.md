# 移动端课表整周可见与信息密度优化

## Goal

手机端（<768px）课表当前横向溢出：`min-w-[760px]` 的 7 列网格在 412px 视口下只露出约 3.5 天，必须横向滚动才能看到后半周；课程块内课名被 `line-clamp-2` 截断、教室被 `truncate` 截断、教师字段完全不显示；节次列只有一个数字，看不到每节的时间。

本次把手机端课表改成：**整周 7 天自适应铺满屏宽（1x 无横向滚动）**，课名按手机"高大于宽"的特性竖排铺满课程块、不做行数截断；节次时间放到最左侧节次列；并提供 **1x~2x 双指缩放**，放大后列变宽并分级显示教室、教师、备注。

## Requirements

### 功能需求

- R1 **整周可见**：手机端（<768px）课表容器在 1x 档位下无横向滚动，周一至周日 7 列全部可见，列宽由可用宽度均分。
- R2 **课名完整**：手机端课程块内的课名不再限制行数（去掉 `line-clamp-2`），按列宽自动换行、纵向铺满课程块，仅在块高不足时被块边界裁剪。
- R3 **节次时间**：最左侧节次列显示该节的开始/结束时间（如 `08:00`/`09:40`），时间不放进课程块内部。时间来源是当前学期课程数据推导，无数据可推导时该节只显示节号。
- R4 **表头信息**：节次列表头显示当前月份（如 `9月`）；每天列显示周几 + 日期（沿用现有 `周一 09.14`）。
- R5 **分级信息**：1x 档位每个课程块显示课名、单双周徽标、考勤状态；放大到 ≥1.5x 增加教室；放大到 ≥2x 增加教师与备注。
- R6 **双指缩放**：在课表区域双指捏合可在 1x~2x 之间缩放，松手后吸附到 `1 / 1.5 / 2` 之一；缩放只改变列宽（列变宽，字不放大），放大后可横向拖动查看其余日期。
- R7 **可达的缩放入口**：除双指捏合外，提供 −/+ 档位按钮，并支持双击切换 1x ↔ 2x，供单指操作或桌面调试使用。缩放控件仅在手机端出现。
- R8 **单双周标记**：课程周次全为奇数时显示 `单周`，全为偶数时显示 `双周`，否则不显示该徽标。
- R9 **桌面端不变**：≥768px 的课表布局、列宽、字号、最小宽度与交互保持现状；缩放能力不在桌面端启用。

### 非功能需求

- N1 **无新增依赖**：只用现有 React / Tailwind / `cn()` / `lucide-react`，不加手势库。
- N2 **缩放流畅**：捏合过程中不逐帧触发 React 重渲染（手势期间直接改 CSS 变量，松手后提交一次状态）。
- N3 **纯逻辑可测**：节次时间推导、单双周判定、档位吸附、缩放范围裁剪写成 feature 内纯函数，并有 vitest 单元测试（`vitest.config.ts` 的 `include` 只匹配 `*.test.ts`）。
- N4 **代码规范**：不用 `any`、`@ts-ignore`、`@ts-expect-error`、`eslint-disable`；条件类名走 `cn()`；新增注释只写在复杂逻辑上（中文 JSDoc）。
- N5 **WebView 兼容**：目标运行环境是 Android Capacitor WebView（Chromium）+ 桌面浏览器；不依赖仅 Firefox 支持的特性，不依赖 `visualViewport` 缩放。

### 约束

- 改动范围限定在 `app/features/schedule/**`；不改 `app/store/**`、`app/routes/**`、`app/lib/**`（除非新增 spec 文档）。
- 缩放档位不持久化，不写入 Zustand store；每次进入课表页默认 1x（整周可见）。
- 不修改 `Class` / `ClassMark` 数据结构与导入解析逻辑。
- 不引入拖拽排课、横屏专项适配、小工具联动等额外需求。

## Acceptance Criteria

### A. 整周可见（1x）

- [ ] A1 412×915 与 360×800 视口下，`document.querySelector('[data-schedule-scroll]')` 的 `scrollWidth === clientWidth`（无横向滚动），且周一~周日 7 个表头列全部在视口内。
- [ ] A2 1440×900 视口下，桌面端渲染结果与改动前一致：仍为 7 列 + `min-w-[760px]`，字号与网格结构未变（对比截图）。
- [ ] A3 窄屏（360px）下每个日期列宽度 ≥ 44px，节次列宽度 ≥ 36px，不出现列宽塌陷到无法阅读（<3 字/行）。

### B. 课程块信息

- [ ] B1 长课名（如 `毛泽东思想和中国特色社会主义理论体系概论`）在 2 节及以上的课程块内完整换行显示，渲染出的文本与 `course.name` 完全一致（无省略号、无 `line-clamp`）。
- [ ] B2 课名元素在 1x 档位的可用宽度不被考勤状态图标挤占（状态图标改为不占文本行宽的位置）。
- [ ] B3 课程块 colspan 与节次块高一致：1 节块课名最多显示到块底被裁剪，不溢出到相邻行。
- [ ] B4 周次全奇数的课程显示 `单周` 徽标，全偶数为 `双周`，混合周次不显示徽标。

### C. 节次时间

- [ ] C1 节次列每行最多显示两行时间（开始 / 结束），来源为当前学期课程数据推导；无法推导的节只显示节号且不留空行占位。
- [ ] C2 课程块内部不再出现任何节次时间文案。

### D. 缩放

- [ ] D1 在课表区域派发双指（两个 `pointerType: 'touch'` 的 PointerEvent，间距翻倍）后，档位从 1x 变为 2x；间距回落后松手吸附回 1x。
- [ ] D2 点 −/+ 按钮可在 `1x → 1.5x → 2x` 之间逐档变化，到边界后按钮为禁用态。
- [ ] D3 双击在 1x ↔ 2x 之间切换。
- [ ] D4 2x 档位下容器 `scrollWidth > clientWidth`（可横向拖动），列宽约为 1x 的两倍，而课程块字号不放大（与 1x 相同）。
- [ ] D5 2x 档位下课程块显示教室；1x 档位下不显示教室与教师。
- [ ] D6 缩放控件在 ≥768px 视口不渲染。

### E. 门禁与回归

- [ ] E1 `pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm test`、`pnpm build` 五项全部通过（不得用抑制手段绕过）。
- [ ] E2 `app/features/schedule/utils.test.ts` 覆盖节次时间推导、单双周判定、档位吸附与裁剪，且用例不依赖当前时刻。
- [ ] E3 手机端仍能正常：点击课程块打开详情弹窗、周次切换按钮、键盘左右键换周、底部导航不被课表遮挡。
- [ ] E4 `pnpm cap:sync:android` 后 Web 资产同步无报错（真机验收由产品负责人在测试版 APK 上执行，作为残余风险记录）。

## Notes

- 参考产品形态（截图来源为其他课程表 App）：7 列铺满一屏、节次列带时间、课程名竖排铺满课程块、放大后信息变多。本次只对齐布局与信息分层，不照搬其视觉主题与配色。
- 缩放档位不持久化：进入课表默认整周概览，避免用户上次放大到 2x 后误以为课表只有 3 天。
- 现有 `docs/课程表行高不齐与竖向滚动条.md`、`docs/mobile-bottom-nav-overlap.md` 记录了此前两轮移动端课表修复，本次若与其中的结论冲突，以本 PRD 为准并在「验证」中说明差异。

## Out of Scope

- 桌面端布局与交互改动。
- 横向滚动式「2~3 天窗口」作为默认布局（只在放大后自然出现）。
- 手势平移惯性、缩放位置记忆、缩放持久化。
- 拖拽创建/移动课程、代课管理相关交互。
- Android 小工具（widget）同步逻辑。
- 横屏/折叠屏专项适配。
