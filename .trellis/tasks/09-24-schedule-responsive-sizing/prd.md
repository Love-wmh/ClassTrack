# 前台课表字号与布局改为随格子尺寸自适应（去掉硬编码 px）

## Goal

把 `app/features/schedule/` 前台课表的字号、内边距、描边与图标尺寸，从「手机 / 桌面两套硬编码 px」改为**由课程格自身尺寸连续推导**的响应式尺度；并新增一个默认关闭的可选开关「收起整周无课的日期列」。

目标状态：任何视口宽度（240–1440 CSS px）、任何缩放档位（1x–2x）、手机 / 平板 / 桌面下，**同尺寸的格子必然同字号**，文字不水平溢出、课名与教室永不丢弃。

---

## 背景（真机实测，证据见 `research/real-device-analysis.md`）

用户真机（视口 360×794 CSS px）截图逐像素分析，网格几何完全符合现有规格，**问题全部在内容尺度**：

| 实测 | 数值 |
| --- | --- |
| 课程格可用文字宽 | **29.6 CSS px** → 10px 中文 = 每行 3 字；20 字课名 = 7–10 行 |
| 14 个有课格子的行距 | **11 格 = 12.00 CSS px**（10px×1.2）／**3 格 = 9.43 CSS px**（9px×1.05）→ **同屏 1.27× 落差** |
| 每节行高 | 62.0 CSS px = `3.875rem` 下界，`1fr` 零余量 → 逐格「放得下吗」只剩 ~3px 余量 |

代码级根因（读代码即可确认，不依赖像素）：

1. **字号与格子尺寸零耦合** —— 唯一开关是 `useIsMobile()`（视口 768px 布尔）+ `md:` 类，字号只有 `text-[10px]`/`text-[9px]` 与 `md:text-sm`/`md:text-xs` 两套硬编码值。
2. **兜底缩字号是 px 硬减且判据错误** —— `baseName = isMobile ? 10 : 14`、`baseRoom = isMobile ? 9 : 12`，每档 `-1px`、最多两档（→ 8px/7px）；档位判据是**视口**而不是格子宽度。同时它把内联 `lineHeight` 从 class 的 `1.2` 改成 `1.05`，把字号落差进一步放大。
3. **收窄内层块只校验高度、不校验宽度** —— `block.style.width = Math.ceil(used)px` 无上限，而 `overflow-wrap: break-word` 不降低 min-content，`(Python)` 这类不可断 token 会把块撑出内边距盒。
4. **测量结论不稳定** —— `fits()` 用 `scrollHeight <= clientHeight + 1`，在 ~3px 余量下，首帧 / `requestAnimationFrame` / `fonts.ready` 三次测量可能给出相反结论 → **同尺寸格子得到不同字号**，这正是「同屏有的格子字正常、有的缩水」的机理。
5. **盒子尺度同为硬编码且与格子不成比例** —— `px-1.5 py-1 md:px-2 md:py-2`、`ring-2`（占卡片宽 4.9%）、出勤角标 `size-3 md:size-4`（占列宽 27%）、表头与节次列 6 处 `text-[Npx]`。
6. **断点混用** —— `ScheduleHeader.tsx` / `SchedulePage.tsx` 用 `sm:`（640px），与 `useIsMobile()` 的 768px / `md:` 割裂。

课表内容是全应用**唯一被压到 10px 以下**的地方（周边 UI 是 12–16px），也是唯一不随尺寸自适应的部分。

---

## 非目标

- 不改网格结构：仍 7 列 × 12 节，不改列数、节数、列序。
- 不改课程数据、学期、出勤语义与配色（`courseColors` / `courseOutOfWeekColors` 保持逐像素采样值）。
- 不破坏 1x 档「整周一次看全 + 无横向滚动」契约（`min-w-[calc(100%*var(--schedule-zoom,1))]`，`ZOOM_MIN` 必须精确等于 1）。
- **不截断课名**（不加 `line-clamp`，不用 `break-all`）。
- 不改缩放交互实现（双指 / 双击 / −+ 按钮 / `--schedule-zoom` 手势期间不 setState）。
- 不改顶栏控件尺寸（`h-9` / `size-4` 是标准 UI 尺度）——顶栏本轮只做断点统一。
- 不动 `data-*` 测试锚点的语义。

## Requirements

### A 组：字号与盒子尺度响应式化（核心）

**A1 唯一真源是格子尺寸。** 课程格字号必须由课程格自身的尺寸连续推导，不得再出现与格子无关的绝对 px 字号。手机 / 桌面不得再各有一套独立数值。

**A2 同尺寸必然同字号。** 字号计算不得依赖「实测后决定」的时序性结论。相同列宽、相同行跨度的课程格，字号必须完全一致（消除 1.27× 落差）。

**A3 尺度体系。** 以下每一项都必须由格子尺寸推导，且互相成比例：课名字号、教室 / 教师 / 备注 / 单双周字号、卡片内边距、卡片描边宽度、出勤角标尺寸、表格头与节次列字号。

**A4 有下限与上限。** 字号必须有可读性下限与（防止大屏上字巨大）上限；下限不得低于 8px。教室行必须比课名行小一档，保持现有信息分级。

**A5 行高唯一。** 名称行高在整个应用内只有一个值（不再出现 class `1.2` 与内联 `1.05` 并存）。

**A6 文字块不得水平溢出。** 课程格内任何文字元素的 `scrollWidth` 不得超过其可用宽度；不可断 token（如 `(Python)`）也不例外。

**A7 兜底必须是相对比例。** 极端尺寸下的缩字号兜底只能按基准字号的**相对比例**递减（并且有硬下限），不得再按固定 px 硬减；同一格子内所有行必须同步缩放，保持行间层级。

### B 组：保留并加固现有空间自适应

**B1 信息显隐优先级不变**：课名 > 教室（两者永不丢弃）> 单双周 / 「非本周」> 教师 > 备注；丢弃顺序反向；只整行隐藏，不裁半截。

**B2 判据改为格子实测尺寸**，不再使用 `isMobile` 视口布尔值来决定「窄格子怎么处理」。

**B3 测量必须稳定可复现**：同尺寸格子在多次测量之间必须得到一致结论（首帧、rAF、`fonts.ready`、ResizeObserver 四条路径不得相互矛盾）。

**B4 不引入每格 setState**，不破坏现有性能约定（手势期间不 setState、`ResizeObserver` 观察外层格子按钮）。

### C 组：断点统一

**C1** `app/features/schedule/` 内不再出现 `sm:` 前缀；统一到 `md:`（768px），与 `useIsMobile()` 一致。

**C2** 页面内边距按 `md:` 分档（`px-2 … md:px-5` 一类），不得出现 640–767px 区间「网格按手机、单元格按桌面」的割裂。

### D 组：新增可选开关「收起整周无课的日期列」

**D1** 新增 `useScheduleDisplayStore` 字段（持久化 key `class-track-schedule-display`），**默认关闭**；在 `ScheduleDisplaySettings` 里提供开关，文案说明「收窄整周没有课程的日期列，把宽度让给有课的日期」。

**D2 关闭时行为必须与现状逐字符一致**：`grid-template-columns` 保持 `2rem repeat(7, minmax(0, 1fr))`（>=768px 时 `4rem`）。

**D3 开启时**：当前展示周内**整周无课**的日期列收窄，有课列获得多出来的宽度；收窄列仍必须完整显示「周几 + 日期」（如 `周六` + `10.03`），不得换行成三行或裁字。

**D4 边界**：全周 7 天都无课时，不得把全部列收窄到不可读（需有最小列宽保护）。

**D5** 收窄只在**当前展示周**判定（翻周时允许列宽变化，这是该开关的既定代价，需在设置项说明里写明）。

**D6** 不改 `data-day-head` 的 7 个元素数量与日期文案，测试锚点不变。

### E 组：可验证性

**E1** 新增必要的 `data-*` 锚点以支撑自动化验收（至少覆盖「教室」元素，当前缺）。

**E2** 现有测试全绿：`ScheduleCourseCell.test.ts`、`ScheduleHeader.test.ts`、`scheduleDisplayStore.test.ts`、`widgetPinPresets.test.ts`、`utils.test.ts`。

**E3** `pnpm typecheck`、`pnpm lint`、`pnpm test` 通过。

## Acceptance Criteria

按优先级排序；**A 组与 D 组的验收互不依赖**（D 组关闭态必须先用 A 组的成果回归一遍）。

### A 组

- [ ] **AC-A1 同尺寸同档位必然同字号**：同一视口下，遍历所有 `[data-course-cell]`，按「**容器内容盒宽 × 行跨度 × 兜底档位**」分组，同组内 `data-course-name` 的 computed `font-size` **完全一致**（无例外）。

  > **实现期按事实收窄**：原本写成「按列宽 × 行跨度分组，同组字号完全一致」，漏掉了兜底档位这一维。兜底是**内容驱动**的（超长课名放不下时按最小必要缩幅缩一档），所以同一尺寸下「20 字课名」与「4 字课名」本来就可以不同字号——这不是缺陷，而是设计（PRD A7）。
  >
  > 原来要钉住的真实缺陷是「**同一个格子在不同测量时机拿到 10px 或 9px**」（时序驱动的差异）。按三维分组 + 精确相等同样能钉死它：时序差异会表现为同组内出现两种字号。
  >
  > 另外单独断言：每个格子的兜底档位必须落在声明的阶梯内（`1` 或 `CELL_FALLBACK_SCALES`），防止出现来路不明的缩放值。
  > 浏览器侧守卫在 `research/verify-responsive-sizing.mjs` 的 `assertCells()`。
- [ ] **AC-A2 参照格单调**：视口宽度 240 / 320 / 360 / 412 / 480 / 600 / 768 / 1024 / 1440 CSS px 逐档推进时，**参照格子**（内容短到永远不触发兜底的那个）的课名字号随列宽**单调不减**，且始终落在 `[8px, 上限]` 内。

  > **实现期按事实收窄**：原本要求「所有课名字号随列宽单调不减」。但兜底档位是内容驱动的跳变，会让同一个格子在不同视口落进不同档位（实测：20 字课名在 412px 落到 0.85、在 360px 落到 0.75），于是序列出现「大视口反而更小」的假象。
  >
  > 单调性本来就是**公式**的性质，已由 `cellScale.test.ts` 的「课名字号随容器宽度单调不减」在两个 ±1px 步长上直接证明。浏览器侧只对不触发兜底的参照格子做序列检查，用来说明「公式在真实 DOM 里也确实单调」。
- [ ] **AC-A3 无水平溢出**：上述每个视口下，对每个 `[data-course-cell]` 内的每个文字元素断言 `scrollWidth <= clientWidth + 1`。必须包含 `(Python)` 这类不可断 token 的课程数据。
- [ ] **AC-A4 硬行永不丢弃**：上述每个视口下，每个 `[data-course-cell]` 的 `data-course-name` 与教室元素的 computed `display !== 'none'` 且 `textContent` 非空。
- [ ] **AC-A5 丢弃顺序守卫**：任一课程格内，若教师可见则课名与教室必须可见；若备注可见则教师必须可见；若单双周可见则教师必须可见。
- [ ] **AC-A6 兜底下限**：构造「1 节矮格 + 20 字课名」的夹具，断言课名字号 `>= 8px` 且无水平溢出。
- [ ] **AC-A7 分级保持**：任何尺寸下 `教室字号 <= 课名字号`（分级不得反转）；在**两者都未触及 8px 下限**的区间内 `教室/课名` 比值恒定，不随视口漂移。

  > **规划期写错、实现期纠正**：本条最初写成「教室字号**严格小于**课名字号，两者比值在 120–240px 视口区间内保持稳定」。这个字面要求在数学上不可能成立——A4 规定两侧下限都不得低于 8px，于是在极窄视口（120–240px）两者同时触底，必然相等。要让「严格小于」到处成立，只能把教室下限压到 8px 以下（如课名 × 0.895 = 7.16px），那又违反 A4。
  >
  > 因此按事实改写：**保序（`<=`）+ 未触底区间内比值恒定**。这仍然覆盖了要修的真实缺陷——改动前的问题是同一个格子在不同测量时机拿到 10px 或 9px（1.27× 漂移），以及判据用视口而不是格子尺寸；改写后的两条都能把它们钉死，而「极窄视口下两行同时触底」是可接受的物理事实，不是缺陷。
  > 公式侧的守卫见 `app/features/schedule/cellScale.test.ts` 的「教室字号永远不超过课名字号，且在两者都未触限的区间内比值恒定」用例。
- [ ] **AC-A8 行高唯一**：`ScheduleCourseCell` 正常态与兜底态下，课名 computed `line-height / font-size` 比值相同。
- [ ] **AC-A8b 内容顶部对齐**：课程格内文字块的垂直起点固定在格子顶边，**不做垂直居中**——1 行内容的格子与 7 行内容的格子必须从同一条顶边起排（否则同一屏里每格的起始高度都不一样）；内容超长时向下溢出并被卡片裁剪，顶部始终可见。
- [ ] **AC-A9 源码守卫**：`app/features/schedule/**` 下不再出现 `text-[<数字>px]`（由单元测试或 lint 规则钉住，防止回归）。
- [ ] **AC-A10 测量稳定**：对同一夹具连续测量两次（含一次 `fonts.ready` 后），所有格子的字号结论完全一致。

### B 组

- [ ] **AC-B1** 1x 下 `[data-schedule-scroll]` 的 `scrollWidth === clientWidth`（无横向滚动）——与现状一致。
- [ ] **AC-B2** 2x 下 `[data-course-cell]` 的课名字号 **>=** 1x 时的字号，且在放得下时教师行可见（缩放仍能揭示更多信息，不退化成正放大镜）。
- [ ] **AC-B3** 桌面端（>=768px）`[data-course-parity]` 仍不渲染（手机端专属信号不回归）。

### C 组

- [ ] **AC-C1** `app/features/schedule/**` 源码中不再出现 `sm:` 前缀。
- [ ] **AC-C2** 640 / 700 / 767 / 768 px 四个视口下，`[data-day-head]` 均为 7 个、`[data-schedule-zoom-control]` 的渲染与 `useIsMobile()` 判定一致（640–767 区间不得出现「网格按手机、单元格按桌面」的混合态）。

### D 组

- [ ] **AC-D1 默认关闭**：`useScheduleDisplayStore` 初始值中该字段为 `false`；未写入过 localStorage 时开关为关闭态。
- [ ] **AC-D2 关闭态零回归**：开关关闭时 `[data-schedule-grid]` 的 computed `grid-template-columns` 与改动前的值**逐字符一致**。
- [ ] **AC-D3 收窄生效**：开启且存在整周无课的日期时，无课列宽 < 有课列宽，且 7 列宽度之和等于容器宽度（不产生横向滚动）。

## 约束与已知限制

- **必须保留**的既有契约：1x 无横向滚动、课名不被截断、`md:` = 768px 与 `useIsMobile()` 一致、手势期间不 setState、`data-*` 锚点语义。
- **已知限制（本轮接受，需写入规格）**：1 节矮格（62px 行高）遇上超长课名时，物理上不可能既保持 >=8px 可读字号、又完整显示 20 个字。取舍已确认：**继续按字换行、不截断；极端情况下允许纵向被卡片裁剪**，但必须保证字号不低于 8px、**绝不水平溢出**。此限制必须在 `mobile-schedule-layout.md` 里写明，避免下次被当成 bug。
- **D 组的既知代价**：翻周时列宽会变化（收窄集合随当前周改变）。这是该开关作为可选功能的固有行为，必须在开关文案里说明。
- **不做**：空列隐藏、列宽过渡动画、把缩放档位改成连续值。

---

## 范围与任务拆分说明

本轮按用户确认的口径做**课表功能全量**：课程格 + 表格头/节次列 + 顶栏断点 + 页面内边距。

**不拆父子任务**，理由：
1. A 组与 D 组改动的是同一批文件（`ScheduleTable.tsx` 同时承载表格尺度与网格列模板），拆成子任务会产生同文件冲突；
2. D 组依赖 A 组定稿的表格尺度才能验证「关闭态零回归」；
3. D 组体量小（一个 store 字段 + 一个设置项 + 一处列模板计算）。

因此本任务内部按 **A → B/C → D** 顺序推进，A 组与 D 组各有独立可验收的 AC（见上），任一组的失败不得阻塞另一组的结论。
